# 子agent、上下文与额度管理

状态：当前采用轻量文档约定；未安装hooks、未改变Codex全局设置。2026-09-12。

截图建议把检索、编码、审查拆给不同子agent，并通过hooks自动保存项目上下文。合理的部分是按任务分工、把经验和当前状态留在项目里；它不保证自动省额度，也不意味着应该每轮写一份长总结。

## 当前采用

- 主agent负责目标、架构与整合；盘点和机械任务选轻量模型；跨模块代码和安全判断用更充分的思考。
- 子任务必须范围明确、可独立完成；只交所需背景，返回文件、结果、验证和风险。
- AGENTS.md保留短规则；docs/worklog/CURRENT.md保留当前状态；方案与决策各自维护唯一文件。
- 新任务先读入口和状态，再按需读具体资料。原始长笔记不每轮全量注入。
- 完成一个有意义的工作块或暂停时更新状态；不要每个Stop都强制重写整份上下文。

Codex原生会发现AGENTS.md，适合放稳定入口和规则。[官方说明](https://learn.chatgpt.com/docs/agent-configuration/agents-md)

## hooks是否要装

官方支持SessionStart、PreCompact/PostCompact、Stop等事件；Stop可触发继续执行，并非天然的“无费用存档按钮”。多个hook可能同时运行，非托管hook需要信任审查。[官方文档](https://learn.chatgpt.com/docs/hooks)

因此本轮先落地文档组织。后续若反复出现漏记，再考虑只提醒CURRENT.md是否更新、或启动时读取短入口的项目级hook。不要让hook无条件阻止结束、重复压缩历史或自行继续任务。未验证本机各事件的实际行为前，不承诺它能可靠自动保存全部上下文。

## 额度和暂停

订阅额度与上下文窗口是不同概念。官方App Server提供account/rateLimits/read；本次读取的是本任务会话中已有的rate-limit快照，没有访问auth.json或账户密钥。[官方接口](https://learn.chatgpt.com/docs/app-server)

用户要求任一相关额度窗口剩余≤2%时收尾。快照有时间差，不能保证并发任务或单次长调用不会越过阈值，因此每个工作块复查并持续保存。没有可靠额度数据时，应明确说明，不能伪造精确硬停保证。

本次用户另行要求北京时间2026-09-12 14:59前暂停，15:00重置后要调整思考程度。这个明确时限优先；暂停后等待用户发出继续指令，不自动恢复或兑换重置。
