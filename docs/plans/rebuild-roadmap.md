# 从 0.0.0 重新建设：让久美子拥有连续的人生

状态：总体方案草案，阶段0源码归零完成、阶段1已覆盖15项源码缺陷与隔离回归，真实设备和故障验收待做。2026-11-01更新。提醒时间契约与[用户位置认知](../decisions/0002-user-location-knowledge.md)已补齐源码与隔离检查。用户目标已确认；后续架构与技术细节分阶段推进，不能把计划当成已实现能力。

## 要解决的实际问题

她需要有自己的生活、认识、需要、目标、承诺和行动。聊天、日记、通知应来自同一段人生；用户不联系时，这段人生仍能延续。主观意识不能由本方案证明，行为和连续性必须能被验证。

现有聊天界面、角色设定、原始历史、RAG、媒体、课表和平台设施可以复用。先补牢事实和状态基础，再提高交流质感。所有 15 组已发现缺陷都进入范围，详见 [审视报告](../reviews/2026-09-12-project-audit.md)，修复进度以 [当前状态](../worklog/CURRENT.md) 和 [本批记录](../worklog/2026-09-12-reliability.md) 为准。

## 第一条完整生活线

选“一周教学里的一个困难”：
周一发现练习问题→产生自己的改进目标→周三课务冲突调整安排→周四行动并记录结果→周五依据经历主动联系。

每一步分别发生和保存。日记可以表达主观感受；不能在周五临时编出周一到周四的事实。模型可提议事件和行动，代码核验来源、权限、预算与执行结果后提交。

## 安全放在哪里

现有 VPS 资源紧且承载网站，[安全方案](../architecture/hosting-security.md)建议私人原型使用独立实例或闲置NAS/小主机，先限本人访问。公网角色API、现有网站、数据库、公共图库必须有清晰边界。任何服务器操作与购买在方案完成后由用户另行授权。

目标架构：客户端只是联络终端；服务器保存权威事件与待办；模型负责理解/提案/表达；工具执行权由独立代码控制。不能让 Prompt 获得 SSH、数据库管理员或 Docker 权限。

## 避免把工程变成堆砌

- 单一久美子主体，职责可以拆模块；不靠多个模型投票决定事实。
- 一份权威事件源；原始事实、他人陈述、模拟世界事件、推测、日记叙事有不同类型。
- 高频时间推进主要用规则；复杂判断才调模型，不必全天每秒生成。
- 不先训练大模型来代替记忆、时间、目标和执行系统。
- 暂不启用GSD、全局hooks或自动推进；先用当前状态、稳定文档和针对性子任务。
- 日常界面与心理数值/内部日志等调试入口分开，减少“操纵角色”的体验。
