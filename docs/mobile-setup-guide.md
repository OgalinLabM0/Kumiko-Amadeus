## 中文教程

## Step 0 · 在电脑和手机上安装 Tailscale

Tailscale 是一条免费的私有隧道。只有登录了同一个 Tailscale 账号的设备才能互相看到，没有任何数据经过第三方服务器。电脑和手机都需要安装并登录同一个账号。

1. 在电脑上下载并安装 Tailscale 客户端（Windows / macOS / Linux 都支持）。
   > 安装过程中会要求登录一次，用你常用的 Google / Microsoft / GitHub 账号登录即可，不需要另注册。
   - [打开 Tailscale 官方下载页](https://tailscale.com/download)

2. 在电脑上启动 Tailscale（Windows 系统托盘会出现一个 Tailscale 图标）。
   > 状态显示 "Connected" 才算登录成功。如果显示 "Logged out" 需要点击重新登录。

3. 在手机上安装 Tailscale App。
   > iOS 走 App Store，Android 走 Google Play（中国大陆需要连外网商店或用 APK）。安装后用和电脑相同的账号登录。
   - [iOS App Store](https://apps.apple.com/us/app/tailscale/id1470499037)

4. 手机上打开 Tailscale App 点一下开关启用 VPN。
   > 开启后手机的 Tailscale IP 会显示在 App 里（类似 100.x.x.x）。这个 VPN 不会加密你正常上网流量，只是让你能看到自己的其他设备。
   - [Android Google Play](https://play.google.com/store/apps/details?id=com.tailscale.ipn)

> **小结**: 完成这一步之后，电脑和手机之间就能通过 Tailscale 互相看到了。下一步是让 Tailscale 给你的电脑签发一张手机能信任的 HTTPS 证书。

## Step 1 · 在 Tailscale 后台开启 HTTPS 证书功能（关键步骤）

iOS Safari / Android Chrome 都不信任自签名证书，所以我们不能用 http:// 或自签 https://。Tailscale 提供了免费的 Let's Encrypt 证书签发功能，但这个功能需要你在网页管理后台手动打开一次，每个账号只需要开一次。

1. 在电脑浏览器里打开 Tailscale 管理后台的 DNS 页面。
   > 这是整个教程最容易漏的一步 —— 如果没开这个开关，启用手机访问时会报错 "your Tailscale account does not support getting TLS certs"。
   - [去 Tailscale Admin · DNS 页面](https://login.tailscale.com/admin/dns)

2. 在页面里找到 "MagicDNS" 部分并确认它已经打开（一般默认是开的）。
   - [什么是 MagicDNS](https://tailscale.com/kb/1081/magicdns)

3. 继续向下滚动，找到 "HTTPS Certificates" 或 "Enable HTTPS" 按钮并点击启用。
   > 开启后你的 tailnet 名字（xxx.ts.net）会被注册到 Let's Encrypt，所有在这个账号下的设备都能用 `tailscale cert` 命令领取证书。

4. 如果按钮不可点，说明你之前没有给 tailnet 起过名字。在同一页顶部有 "Tailnet name" 输入框，随便起一个英文名字后就能开了。

> **小结**: HTTPS Certificates 是账号级别的开关，开一次之后再也不用关心。Kumiko 下次启用手机访问时会自动调用 `tailscale cert` 命令为你的电脑签发证书。

## Step 2 · 在 Kumiko 里启用手机访问，拿到地址和口令

前两步一次性配置，之后都不用再动。这一步是 Kumiko 本地的真正"开关"。

1. 在 Kumiko 桌面版打开"设置 → 手机远程访问"面板。

2. 点击"启用手机访问"按钮。
   > 第一次启用会触发 Windows Defender 防火墙弹窗，选"允许"即可。Fastify 会绑定到 0.0.0.0 的一个随机高端口，只有 Tailscale 隧道内的设备能访问。

3. 等待 10-30 秒，面板会显示"运行中"并出现"连接信息"卡片。
   > 如果一直卡在"未运行"，看下方 Step 4 对应的错误码。

4. 把"手机访问地址"复制下来（形如 https://your-device.your-tailnet.ts.net:xxxxx/）。

5. 点"显示口令"再点"复制"，把 64 位十六进制的配对口令复制下来。
   > 这个口令是一次性的 —— 手机首次配对成功后就会失效。之后手机靠 Cookie 记住身份，直到你手动"吊销会话"。

## Step 3 · 在手机上配对并添加到主屏幕

手机 App 本质上是一个 PWA（Progressive Web App）—— 用系统浏览器打开桌面提供的 HTTPS 地址，然后把它"添加到主屏幕"就变成类似原生 App 的启动入口。

1. 确保手机上的 Tailscale VPN 是开启状态（App 里开关打到绿色）。
   > 如果忘记开 VPN，会打不开 .ts.net 地址。

2. 用手机系统浏览器打开 Step 2 里复制的"手机访问地址"。
   > iOS 必须用 Safari（Chrome 也行但不能"添加到主屏幕"触发 PWA）；Android 推荐 Chrome。

3. 页面会显示 Kumiko·Amadeus Mobile 配对界面。把口令粘贴进输入框，点 Pair phone。
   > 成功后自动跳转到聊天界面，可以立即发消息。

4. （可选但强烈推荐）把当前页面添加到主屏幕。
   > iOS Safari：底部分享按钮 → "添加到主屏幕"。Android Chrome：右上角菜单 → "添加到主屏幕"。之后从主屏幕启动时是独立窗口、没有浏览器地址栏，和原生 App 一样。

> **小结**: 配对成功后的 Cookie 有效期 90 天，超过 90 天或你手动"吊销会话"后需要重新粘贴口令配对。

## Step 4 · 常见错误诊断

下面列出启用手机访问时可能遇到的错误码，以及每种错误对应的排查步骤。面板里的红色错误卡片会显示错误码，对照这张表就能知道怎么修。

### `E_NO_HTTPS_FEATURE`

**现象 / Symptom**: 红色错误卡片显示 "your Tailscale account does not support getting TLS certs"。

**原因 / Cause**: 你的 Tailscale 账号还没开启 HTTPS Certificates 功能。这是 Tailscale 后台的一个账号级开关，必须手动打开一次。

**修复 / Fix**:
1. 在电脑浏览器打开下方的 Tailscale Admin · DNS 页面
2. 确认 MagicDNS 已开启
3. 找到 HTTPS Certificates 按钮点击启用
4. 回到 Kumiko 面板再次点击"启用手机访问"

➜ [去 Tailscale Admin 开启 HTTPS Certificates](https://login.tailscale.com/admin/dns)

### `E_NO_CLI`

**现象 / Symptom**: 红色错误卡片显示 "tailscale CLI not found"，或 Tailscale 状态显示"未检测到 Tailscale"。

**原因 / Cause**: 电脑上还没装 Tailscale 客户端，或者装了但 `tailscale.exe` 不在 PATH 里（部分 Windows 安装会这样）。

**修复 / Fix**:
1. 到官方下载页下载并安装 Tailscale 客户端
2. 安装后打开 Tailscale App 并登录账号
3. 系统托盘出现 Tailscale 图标且状态显示 Connected
4. 回到 Kumiko 面板重新点击"启用手机访问"

➜ [打开 Tailscale 官方下载页](https://tailscale.com/download)

### `E_NOT_LOGGED_IN`

**现象 / Symptom**: Tailscale 状态显示"已安装但未登录/未连接"，或红色卡片提到 "backend state"。

**原因 / Cause**: Tailscale 客户端已安装但账号没登录成功，或者 VPN 服务停止了。

**修复 / Fix**:
1. 打开 Tailscale 客户端
2. 确认右下角显示 Connected（绿色）而不是 Logged out / Stopped
3. 如果是 Logged out 就点 "Log in" 重新登录
4. 回到 Kumiko 面板重试

➜ [查看设备连接状态](https://login.tailscale.com/admin/machines)

### `E_CERT_TIMEOUT`

**现象 / Symptom**: 启用按钮卡了 90 秒后报超时错误，面板显示"未运行"。

**原因 / Cause**: Tailscale 客户端反应太慢、ACME 签发失败、网络不稳定，或者刚刚才开启 HTTPS Certificates 需要等几分钟让 Tailscale 后台同步。

**修复 / Fix**:
1. 确认电脑能正常访问互联网（不只是 Tailscale 网络）
2. 等 2-3 分钟再点一次"启用手机访问"
3. 如果连续失败超过 3 次，重启 Tailscale 客户端后再试
4. 仍然失败的话把 Step 1 的 HTTPS Certificates 按钮关掉再重新打开

### `E_CERT_FAILED`

**现象 / Symptom**: 红色卡片显示 "tailscale cert failed" 或其他 cert 相关错误。

**原因 / Cause**: ACME 签发证书失败。常见原因是 tailnet 名字之前被 Let's Encrypt 限流，或者 Tailscale 后台签发配额用完了。

**修复 / Fix**:
1. 等 1 小时之后再重试（Let's Encrypt 的 rate limit 是按小时计算的）
2. 如果 1 小时后仍然失败，到 Admin 后台检查 HTTPS Certificates 开关状态
3. 仍然失败可以在 Admin 页面给你的机器起一个新名字，再触发一次签发

➜ [查看 Tailscale HTTPS 文档](https://tailscale.com/kb/1153/enabling-https)

### `E_LISTEN_EADDRINUSE`

**现象 / Symptom**: 启用时报错 "listen EADDRINUSE" 或"端口被占用"。

**原因 / Cause**: 之前 Kumiko 崩溃或非正常退出，留下了一个没释放的端口。或者有别的软件占了同一个端口。

**修复 / Fix**:
1. 完全退出 Kumiko（托盘图标右键 → 退出）
2. 等 10 秒让系统释放端口
3. 重新打开 Kumiko，点"启用手机访问"
4. 如果仍然冲突，重启电脑让所有端口重置

### `E_LISTEN`

**现象 / Symptom**: 启用时报 "EACCES" 或其他 listen 错误（非端口占用）。

**原因 / Cause**: 操作系统拒绝了绑定端口的请求，通常是防火墙或安全软件拦截。

**修复 / Fix**:
1. 在 Windows Defender 弹出的防火墙提示里点"允许"
2. 如果装了第三方安全软件（360、腾讯电脑管家等），临时关闭它再试
3. 确认 Kumiko 是正常安装启动，不是绿色版解压到系统目录里

### `E_BUILD`

**现象 / Symptom**: 启用时报 "E_BUILD" 或 Fastify 初始化失败。

**原因 / Cause**: Fastify 服务本身初始化异常，通常是安装包损坏或依赖缺失。

**修复 / Fix**:
1. 重装最新版 Kumiko
2. 安装时选"覆盖安装"不会丢数据
3. 仍然失败可以把详细错误贴到 GitHub issue

> **小结**: 还有其他错误没列在这里？欢迎到项目 GitHub 仓库提 issue，附上红色错误卡片里的完整文本。

## English Guide

## Step 0 · Install Tailscale on your computer and phone

Tailscale is a free private tunnel. Only devices logged into the same Tailscale account can see each other — no traffic flows through third-party servers. You need Tailscale on both the desktop and the phone, signed into the same account.

1. Download and install the Tailscale client on your computer (Windows / macOS / Linux all supported).
   > The installer asks you to log in once. Use a Google / Microsoft / GitHub account you already own — no separate signup needed.
   - [Open Tailscale download page](https://tailscale.com/download)

2. Launch Tailscale on your computer (on Windows a Tailscale icon will appear in the system tray).
   > The tray should read "Connected". If it says "Logged out" click Log in.

3. Install the Tailscale app on your phone.
   > iOS: App Store. Android: Google Play. Sign in with the same account you used on desktop.
   - [iOS App Store](https://apps.apple.com/us/app/tailscale/id1470499037)

4. Open the Tailscale app on your phone and flip the VPN switch on.
   > Your phone will pick up a Tailscale IP (100.x.x.x). This VPN does NOT route your normal internet traffic — it only lets your own devices see each other.
   - [Android Google Play](https://play.google.com/store/apps/details?id=com.tailscale.ipn)

> **Summary**: Once both devices are on Tailscale, your phone can see your desktop. Next step is to let Tailscale hand out an HTTPS certificate your phone will trust.

## Step 1 · Enable HTTPS Certificates in the Tailscale admin (critical)

iOS Safari and Android Chrome refuse self-signed certificates. Tailscale offers free Let's Encrypt issuance, but the feature is account-level and must be flipped on from the web admin. You only need to do this once per Tailscale account.

1. Open the Tailscale admin DNS page in your desktop browser.
   > This is the most-missed step — skipping it means enabling Mobile Access fails with "your Tailscale account does not support getting TLS certs".
   - [Open Tailscale Admin · DNS](https://login.tailscale.com/admin/dns)

2. Verify that MagicDNS is enabled (it usually is by default).
   - [What is MagicDNS](https://tailscale.com/kb/1081/magicdns)

3. Scroll down to "HTTPS Certificates" (a.k.a. "Enable HTTPS") and click to enable.
   > Enabling it registers your tailnet (xxx.ts.net) with Let's Encrypt. Any device in this account can then mint certificates via `tailscale cert`.

4. If the button is greyed out, you haven't named your tailnet yet. Use the "Tailnet name" input at the top of the page, pick any name, and the toggle becomes available.

> **Summary**: HTTPS Certificates is an account-level switch — once on, you never touch it again. Next time you hit Enable in Kumiko the desktop runs `tailscale cert` on your behalf.

## Step 2 · Flip Mobile Access on in Kumiko and grab the address + token

The first two steps were one-time setup. This is the only part you repeat day-to-day.

1. Open Settings → Mobile Remote Access in desktop Kumiko.

2. Click Enable mobile access.
   > The first enable triggers Windows Defender's firewall prompt — choose Allow. Fastify binds 0.0.0.0 on a random high port, only reachable through the Tailscale tunnel.

3. Wait 10-30 seconds until the panel reads "Running" and the Connection card appears.
   > Stuck at "Stopped"? See the Step 4 troubleshooting table for the specific error code.

4. Copy the Phone URL (shaped like https://your-device.your-tailnet.ts.net:xxxxx/).

5. Click Reveal token then Copy to grab the 64-char hex pairing token.
   > The token is one-use — once a phone pairs successfully it is invalidated. The phone remembers the session via a secure cookie (90 days) until you manually revoke it.

## Step 3 · Pair your phone and add to home screen

The phone app is actually a PWA (Progressive Web App). You open the desktop's HTTPS URL in your phone's system browser, then "Add to Home Screen" turns it into a launcher that behaves like a native app.

1. Make sure the Tailscale VPN on your phone is enabled (switch is green in the Tailscale app).
   > If the VPN is off the .ts.net URL will not resolve.

2. Open the Phone URL you copied in Step 2 in your phone's system browser.
   > iOS must use Safari (Chrome will load the app but cannot "Add to Home Screen" as a PWA). Android: Chrome is recommended.

3. The Kumiko·Amadeus Mobile pairing screen appears. Paste the token and tap Pair phone.
   > On success you're immediately thrown into the chat screen and can send messages right away.

4. (Optional but strongly recommended) Add the page to your home screen.
   > iOS Safari: Share button → Add to Home Screen. Android Chrome: menu → Add to Home Screen. Launching from the home screen removes the browser chrome and feels like a native app.

> **Summary**: Pairing cookies last 90 days. Expire or revoke-all triggers a re-pair with a fresh token.

## Step 4 · Troubleshooting table

Error codes you may see when enabling Mobile Access. The red error card in the Settings panel prints the code — cross-reference this table to know what to do next.

### `E_NO_HTTPS_FEATURE`

**现象 / Symptom**: Red error card says "your Tailscale account does not support getting TLS certs".

**原因 / Cause**: Your Tailscale account hasn't enabled HTTPS Certificates yet. It's a one-time, account-level toggle in the Tailscale admin.

**修复 / Fix**:
1. Open the Tailscale Admin · DNS page in your browser
2. Confirm MagicDNS is on
3. Scroll down and click the HTTPS Certificates toggle to enable
4. Come back to Kumiko and click Enable mobile access again

➜ [Enable HTTPS Certificates in Tailscale admin](https://login.tailscale.com/admin/dns)

### `E_NO_CLI`

**现象 / Symptom**: Red error card says "tailscale CLI not found", or Tailscale status reads "Tailscale CLI not detected".

**原因 / Cause**: Tailscale isn't installed on the desktop, or it is installed but `tailscale.exe` isn't on PATH (common on some Windows installs).

**修复 / Fix**:
1. Install the Tailscale client from the official download page
2. Open the Tailscale app after install and log in
3. Confirm the tray icon reads Connected
4. Come back to Kumiko and click Enable mobile access

➜ [Open Tailscale download page](https://tailscale.com/download)

### `E_NOT_LOGGED_IN`

**现象 / Symptom**: Status reads "installed but not logged in / connected" or the card mentions "backend state".

**原因 / Cause**: Tailscale is installed but the account session died, or the VPN service was stopped.

**修复 / Fix**:
1. Open the Tailscale client
2. Verify the tray reads Connected (green), not Logged out / Stopped
3. If Logged out, click Log in again
4. Retry from Kumiko

➜ [Check device connection state](https://login.tailscale.com/admin/machines)

### `E_CERT_TIMEOUT`

**现象 / Symptom**: The Enable button hangs for 90 seconds and errors out; the panel shows "Stopped".

**原因 / Cause**: Tailscale is slow, ACME issuance stalled, your network is flaky, or you just turned on HTTPS Certificates and the backend hasn't propagated yet.

**修复 / Fix**:
1. Confirm the computer has working internet (not just Tailscale)
2. Wait 2-3 minutes and click Enable again
3. If it fails 3+ times, restart the Tailscale client and retry
4. Still failing? Toggle HTTPS Certificates off and back on from the admin

### `E_CERT_FAILED`

**现象 / Symptom**: Red card reads "tailscale cert failed" or similar cert issuance error.

**原因 / Cause**: ACME issuance failed. Usually Let's Encrypt rate-limited the tailnet or the quota is temporarily exhausted.

**修复 / Fix**:
1. Wait an hour and retry (Let's Encrypt rate limits reset hourly)
2. After waiting, check the HTTPS Certificates toggle in admin
3. As a last resort rename the machine in admin and retry

➜ [Read Tailscale HTTPS docs](https://tailscale.com/kb/1153/enabling-https)

### `E_LISTEN_EADDRINUSE`

**现象 / Symptom**: Error reads "listen EADDRINUSE" or "port in use".

**原因 / Cause**: A previous crash of Kumiko left the port bound, or another app is using the same port.

**修复 / Fix**:
1. Fully quit Kumiko (tray → Quit)
2. Wait 10 seconds for the OS to release the port
3. Re-open Kumiko and click Enable
4. If still conflicting, reboot to reset all port bindings

### `E_LISTEN`

**现象 / Symptom**: Error reads "EACCES" or other listen error (not a port conflict).

**原因 / Cause**: The OS refused the bind, usually a firewall or security suite blocking it.

**修复 / Fix**:
1. Accept the Windows Defender firewall prompt (click Allow)
2. If you run a 3rd-party AV (360, Norton, etc.), temporarily disable it and retry
3. Make sure Kumiko was properly installed, not extracted into a system directory

### `E_BUILD`

**现象 / Symptom**: Error reads "E_BUILD" or Fastify initialization failed.

**原因 / Cause**: Fastify itself failed to start, usually a corrupted install or missing dependency.

**修复 / Fix**:
1. Reinstall the latest Kumiko build
2. Choose "overwrite" during install — your data is preserved
3. Still failing? File an issue on GitHub with the full error text

> **Summary**: Hit an error not listed here? Please open a GitHub issue and paste the full contents of the red error card so we can add it to the table.
