# 持续生活服务器与安全方案

状态：方案草案，未部署。资料核验于2026-09-12，现机规格来自用户指定管理知识库的历史快照，未登录服务器检查实时负载。

## 现有 VPS 能不能用

原理上可以，域名也可以复用。但现机是 RackNerd、Debian 12、amd64、1 vCPU、约1.9 GB RAM + 1 GB swap、39 GB磁盘；2026-08-30资料记载磁盘使用38%。精确机房地区未知，EDT仅是服务器时区。

它已有 nginx、Cloudreve、Alist、MySQL、Redis、Node搜索API、1Panel及多个站点。80/443已由nginx使用。文档有若干服务监听全部接口的记录；实际公网暴露还取决于防火墙，不能仅凭监听地址下定论。

**建议保留现机原业务，角色原型用独立实例或独立家用设备。** 2核4GB可作为使用外部模型API的试验起点，4核8GB更宽裕；这是容量规划建议，不是已跑负载测试的最低配置，也不要求现在购买。若只用现机试验，需先核对实时余量、容器限额及恢复能力，不能直接托管唯一的权威人生数据。

已有公共图库不适合角色私密媒体。对象存储应另建私有桶和独立权限；不要复用现有网站的数据库、管理凭据或容器网络。角色时间使用UTC存储、显式日本/用户时区，不继承VPS的系统时区。

本地资料位置：用户指定“OMKK 网站与服务器管理/wiki/notes/服务器配置.md”和“服务拓扑.md”。本仓库只保存脱敏结论，不复制密码、私钥、IP清单或管理入口。

## 推荐部署阶段

| 模式 | 适合谁 | 代价与边界 |
|---|---|---|
| 本机运行 | 不需要关机后继续生活的用户 | 休眠/关机时暂停 |
| NAS/小主机或独立VPS + 私网 | 本人原型、自托管爱好者 | 维护设备和备份；可不需要公网域名 |
| 独立VPS + 公网HTTPS | 自己配置服务器的用户 | 必须完成认证、设备撤销、限速、升级和恢复 |
| 项目方托管 | 普通用户 | 不必买VPS；项目承担隐私、安全、费用和可用性责任 |
| 共享多租户托管 | 扩大用户规模后 | 必须证明租户在所有数据和任务路径隔离，最后推进 |

私人原型：API + 持久Worker + PostgreSQL任务表/outbox + Compose即可；外部模型API负责推理，VPS不必配GPU。Tailscale Serve限制在私人网络，Funnel会公开服务，不能混用。[官方说明](https://tailscale.com/docs/features/tailscale-funnel/how-to/host-websites)

当前软件没有这套角色服务器。已有“模型自定义地址”不能代替角色服务器地址；需要新增设备配对、状态同步和后台工作流。

## 分发后，用户怎样连接自己的服务器

1. 用户准备VPS/NAS，安装统一版本的部署包，无须复制源码或维护个人分支。
2. 私网模式加入自己的设备网络；公网模式给新子域设置DNS，接入现有反向代理或独立主机，不能抢占现有站点端口。
3. 初始化向导生成独立实例密钥、数据库凭据和管理员恢复信息，模型Key在服务器录入。
4. 健康检查通过后，生成短时有效、只能使用一次的配对码。
5. 软件选择“连接自己的服务器”，输入HTTPS地址并扫码；用户不需要填写数据库密码。
6. 设备取得短期访问令牌及可撤销会话；凭据进入系统安全存储。
7. 做一次关闭客户端、后台运行、重新连接和恢复备份的验收，再投入长期使用。

HTTPS可由反向代理自动管理证书；Caddy能自动申请和续期，但在现有nginx主机上应先规划入口，不能直接另起服务占80/443。[Caddy文档](https://caddyserver.com/docs/automatic-https)

## 安全验收门槛

- 公网仅提供所需HTTPS入口；数据库、Worker、Docker管理接口不对公网开放。
- 配对码短时、单用、限速；访问令牌短期；刷新会话按设备轮换和撤销。令牌权限/接收方应收窄。[OAuth安全最佳实践](https://www.rfc-editor.org/info/rfc9700/)
- 模型只能提出行动；执行器核对允许的工具、对象、预算、幂等和权限，模型无管理员凭据。
- 共享托管的请求、任务、检索、媒体、缓存均绑定经过认证的tenant与角色实例。数据库RLS作为附加隔离；应用角色不能绕过RLS。[PostgreSQL文档](https://www.postgresql.org/docs/current/ddl-rowsecurity.html)
- 共享服务中的自定义外部URL需防SSRF：供应商白名单、目标地址/DNS/重定向验证、超时和响应上限。自托管本地模型若需内网地址，必须由实例管理员明确登记在独立规则中，不能通过普通用户输入开放任意内网访问。[OWASP说明](https://cheatsheetseries.owasp.org/cheatsheets/Server_Side_Request_Forgery_Prevention_Cheat_Sheet.html)
- 私人媒体使用授权读取，不放公共图库；日志默认不记录聊天正文、日记、Key或会话令牌。
- 多代加密备份放另一故障域，并实际恢复；卷存在不等于备份。[Docker存储文档](https://docs.docker.com/engine/storage/volumes/#back-up-restore-or-migrate-data-volumes)
- 升级固定版本/镜像，迁移前备份，验证失败能够恢复；为模型并发、费用和任务重试设上限。
- 上线前测试未授权访问、跨租户读取、配对重放、令牌撤销、恶意URL、超大上传、重复任务、断网和数据库恢复。

## 隐私边界

服务器负责组装记忆和模型上下文时，运行中的服务器能够处理所需明文；外部模型也会收到选入请求的内容。TLS和静态加密分别保护传输与存储，不能把这套架构宣传为服务器看不见内容的端到端加密或零知识。

本轮没有连接服务器、改DNS、部署软件、读取凭据页或购买资源。下一步的服务器动作需要在方案明确后由用户另行授权。
